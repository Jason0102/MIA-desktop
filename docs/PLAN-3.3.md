# MIA 3.3 開發計畫（待審核，尚未實作）

日期：2026-11-17。此分支目前只保存規劃，不代表任何項目已實作或獲准開發。

## 版本目標

- 3.1：高互動性的桌寵介面。
- 3.2：Hermes 整合的多用途個人助理。
- 3.3：隨互動逐漸了解使用者、累積合作經驗，具有互動記憶與持續心情的個人化助理。

核心流程：互動事件 → 每日／每週記憶 → 持續心情 → 結合當下對話 → 情緒標籤 → 文字、動畫、語音。
長期個性、持續心情、當句情緒分開管理。

## 開發項目

1. **統一互動紀錄（必要）**：保存使用者、來源管道、時間、事件類型、對話／任務識別與時長。統計非任務發話及聊天段數、閒聊話題及可信度、新任務／續接／完成／失敗／取消、游標靠近／停留／點擊／摸頭／拖曳、陪玩場次／投球次數／有效時長、明確回饋與陪伴時間。同人 PC／Discord 可合併或分開查看，不同使用者隔離。混合訊息可多類標記，但總發話數不重複。
2. **計數規則（必要）**：聊天輪次與段落分開，段落暫以閒置 10 分鐘切分，待實測調整。游標事件去抖及冷卻；使用者陪玩與自主玩球分開。鎖屏、休眠、暫停不累加有效時長；異常退出依最後有效紀錄結算。訊息重送、同步、工具重試及子任務不算新指派。
3. **每日／每週記憶（必要）**：今日、本週、近 7 天、近 30 天統計；按使用者時區切日，預設週一起算，跨午夜拆分時長。產生日／週摘要、常見話題及習慣變化，摘要保留事件來源。歷史缺少的資料標記未知，不補造數據。
4. **MIA 後台資訊（必要）**：互動概況與趨勢、話題及偏好修正、心情維度及成因、每句情緒／動畫／語音選擇追蹤。初期為進階資訊頁，保留簡潔桌寵介面，亦可用對話詢問心情。
5. **持續心情模型（必要）**：愉悅度、活力、親近感、玩心四維。角色基準加近期有效互動加權及緩慢長期趨勢，隨時間回歸基準。相同事件邊際遞減並限制每日影響；親近感慢變、活力及玩心快變。工作完成也屬正向共同經驗；少互動或大量派工不造成懲罰。初期規則可解釋、權重可調，資料不足用預設值。
6. **對話／動畫／語音整合（必要）**：提供心情快照、相關記憶與偏好；當句內容決定最終情緒，持續心情為參考。沿用現有標籤及動畫建立映射，三種表達共用結果。保留拖曳、掉落、停靠、任務與語音優先順序；語音失敗仍有文字及動畫。細部音高／語速控制待服務能力確認。
7. **完整記憶重置（必要）**：清除該使用者的對話、長期記憶、互動事件、統計、話題摘要、學習偏好、親近感、心情歷史、共同回憶、相關快取及衍生索引。回復角色初始心情，保留角色基本設定、服務設定與工作成果。PC／Discord 同步更新記憶版本，防止舊會話及在途請求寫回；部分失敗不得宣稱全部成功。
8. **資料管理及驗收（必要）**：本機保存為主，模型僅取所需摘要；可停用記錄、刪除話題、修正偏好及設定保存期限。事件、摘要及心情計算解耦，不為游標事件逐次呼叫模型。驗收跨日週、重啟、休眠、連點、自主玩球、去重、使用者隔離與重置不回流。
9. **可修正偏好檔案（優先）**：回答長度、語言、提醒、交付格式及聊天風格；區分明確指定與推測，保留來源、可信度及修改／撤銷入口。
10. **工作默契記憶（優先）**：從修改及審核回饋整理完成標準、草案需求、常用模板與驗證習慣。學習不能擴大操作授權。
11. **共同話題續接（優先）**：保留未聊完且適合再提的主題，相關時自然銜接；有過期、冷卻及不要再問設定。
12. **打擾時機（優先）**：依設定、MIA 任務及既有行事曆選擇招呼、語音與邀請時機。先提供安靜／適中／活潑，依明確回饋微調；冷卻、每日上限、無回應降低頻率，忽略不視為負面情緒。
13. **共同回憶卡與週記（擴充）**：從有來源的共同任務及閒聊產生可收藏小卡與週記，不虛構事件；預設使用者查看，推送另設開關。
14. **專屬小習慣（擴充）**：形成個人化招呼、工作完成動作、遊戲開場與晚間儀式，可關閉，不要求每日互動。
15. **可控個性成長（擴充）**：沉穩／活潑、簡潔／健談、主動／安靜等傾向緩慢調整，保留原人設，使用者設定優先。

## 追加需求：漸進自主學習（待審核）

使用者希望米亞隨互動逐漸了解使用者，並改善任務處理與互動能力。

### 3.2 現況與限制

- `src/Mia/Services/HermesService.cs` 已指示先以 skills_list／skill_view 查讀技能；使用者要求維護，或完成可重複的非例行工作且取得已驗證方法後，以 skill_manage 新增或修訂，並重新讀取確認。這是已接入的代理工作流程，不保證每次會自主執行或寫入成功。
- 同處要求技能保留可重用的前提、步驟及驗證，避免重複，不記個人資訊、憑證及單次內容，不擴大權限。
- 長期記憶明確限制為「使用者要求記住的偏好與資訊」，因此尚非主動持續整理使用者特徵的完整機制。
- `integration/hermes/mia_shared_memory.py` 提供同身分跨 PC／Discord 共用長期記憶及提示詞版本刷新；技能目前依各管道 profile 保存，並非等同跨管道共用技能庫。
- 本次只做靜態程式與文件檢查，未測試實際自主學習或呼叫付費模型。沒有證據支持已具備定期自主回顧、技能成效評分及閉環優化。

### 新增開發項目

16. **經驗回顧與學習候選**：任務完成、使用者修正或重複失敗後，整理有效做法、錯誤原因及候選偏好；區分已驗證結果與模型推測。採事件觸發與批次回顧，限制成本及頻率。
17. **技能演進閉環**：查找既有技能 → 提出新增／修訂 → 適用情境驗證 → 保存版本 → 後續使用追蹤。記錄成功率、重試及人工修正，退化時回退；技能內容不含個資，權限政策獨立。跨管道共享可重用技能的範圍另訂規格。
18. **使用者特徵整理**：將反覆出現的互動模式先列為候選，附來源、可信度及有效期限；明確指示優先，矛盾可修正，不從少量互動武斷推定人格或敏感特徵。與第 9、10 項合併設計。
19. **學習透明度與控制**：後台顯示最近學到了什麼、依據及應用效果；可禁止學習、撤銷單項、回退技能。記憶重置一併清除使用者衍生特徵、學習候選及個人化流程；通用技能是否保留需在重置規格明確區分，不能攜帶已刪除個資回流。

這裡的學習指記憶、技能及策略的持久更新，不是重新訓練底層模型，也不授權自行修改程式、安裝工具或擴張權限。

## 建議順序與審核範圍

- A 規格：事件、計數、心情、記憶與學習重置邊界。
